# ⚡ NetPulse — Real-Time Network Quality Monitor

**NetPulse** — это легковесный, высокопроизводительный инструмент для непрерывного мониторинга качества сетевого соединения в реальном времени, сетевой диагностики и анализа стабильности каналов связи.

---

## 🌟 Ключевые возможности

1. **Многопротокольный параллельный Ping Engine (ICMP & TCP)**:
   - Непрерывный асинхронный опрос заданных узлов (Cloudflare DNS, Google DNS, Yandex DNS, Quad9, локальный шлюз).
   - Режимы: `auto` (сначала TCP, при неудаче — системный `ping`), `tcp` (не требует прав root/Admin), `icmp` (сырые сокеты; без прав автоматически используется системный `ping`) и `subprocess` (системный `ping`).
   - В режиме TCP узел считается живым и тогда, когда порт закрыт, но хост ответил `RST`. Время DNS-запроса в RTT не входит (имена кэшируются на 5 минут).

2. **Математический анализ качества соединения (RFC 3550 Jitter & Latency)**:
   - Расчет межпакетного джиттера в строгом соответствии со стандартом **RFC 3550** ($J_i = J_{i-1} + \frac{|D| - J_{i-1}}{16}$).
   - Перцентили задержки (**P50 / Median**, **P95**, **P99**), минимальный, средний и максимальный RTT.
   - Процент потерь пакетов (**Packet Loss %**): за скользящее окно истории и за всю сессию.

3. **Статусы и алерты**:
   - `DOWN` — три проверки подряд неудачны (`down_after_failures`); `CRIT` / `WARN` — по порогам задержки, джиттера и потерь за последние 20 проверок (потери оцениваются, когда накоплено не менее 10 проверок).
   - Алерты «по фронту»: одно событие на появление/усиление проблемы, повтор — не чаще раза в минуту; при возврате в норму — одно событие «узел снова в норме».
   - Звуковой сигнал (`--sound`) срабатывает на предупреждения и сбои, но не на восстановление.

4. **Сетевая диагностика и авто-MTR / Traceroute**:
   - Автоматическое определение локального IP, основного шлюза (Default Gateway), DNS-серверов; смена сети (новый шлюз) подхватывается автоматически. Если значение определить не удалось, показывается «не определён», а не выдуманное.
   - Определение публичного IP, страны, города и интернет-провайдера (ISP / AS).
   - **Auto-MTR**: при критическом алерте (узел недоступен, потери ≥ 8 %, задержка ≥ 180 мс, джиттер ≥ 40 мс) автоматически запускается трассировка — не чаще одной за раз и не чаще раза в 2 минуты на узел. Требуется утилита `traceroute` (Linux/macOS) или `tracert` (Windows); если её нет, интерфейс сообщает об этом.

5. **Замер пропускной способности (Bandwidth & Speedtest)**:
   - Встроенный асинхронный замер скорости скачивания (**Download Mbps**) и отдачи (**Upload Mbps**) через CDN-эндпоинты Cloudflare по горячей клавише `[S]`. Скорость считается без учёта DNS/TLS и ожидания первого байта. Если отдачу измерить не удалось, результат помечается как неполный, а не как успешный.

6. **Премиальный интерфейс (Dual Mode)**:
   - **Rich Interactive TUI**: терминальный дашборд с sparkline-графиками, цветовой индикацией статусов, журналом аномалий и панелью управления.
   - **Web Dashboard**: веб-интерфейс с графиком **Chart.js** в реальном времени (библиотека лежит локально — панель работает без интернета), доступный по флагу `--web`.

7. **Долговременное хранение и экспорт**:
   - Автоматическое логирование всех измерений в базу данных **SQLite** (`netpulse_history.db`, режим WAL; записи старше 30 дней удаляются при старте).
   - Экспорт детальных отчетов сессии в форматы **JSON** и **CSV** (значения, похожие на формулы Excel, экранируются).

## 🔒 Безопасность веб-интерфейса

API не требует авторизации, поэтому по умолчанию сервер слушает **только `127.0.0.1`**, а каждый запрос проверяется:
заголовки `Host`, `Origin` и `Sec-Fetch-Site` должны указывать на сам дашборд. Это закрывает запуск замера скорости и создание отчётов с чужих сайтов (CSRF) и чтение данных через DNS-rebinding. Страница работает под строгой Content-Security-Policy (никаких inline-скриптов, внешних CDN и шрифтов), а данные узлов выводятся как текст, а не как HTML.

## 🚀 Установка и запуск

### Требования
* **Python 3.11+**
* Операционная система: Windows, Linux или macOS.

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

> **Примечание**: без `fastapi` и `uvicorn` веб-интерфейс работает на встроенном `http.server` (те же маршруты и те же проверки безопасности), поэтому для терминального режима достаточно библиотеки `rich`.

Либо как пакет с командой `netpulse`:
```bash
pip install .
netpulse --help
```

### 2. Запуск TUI-монитора в терминале
```bash
python main.py
```

### 3. Запуск с веб-интерфейсом
```bash
python main.py --web --port 8080
```
После запуска откройте в браузере: `http://127.0.0.1:8080`. Если порт занят, приложение сообщит об этом до запуска интерфейса.

### 4. Мониторинг пользовательских хостов
```bash
python main.py --hosts "1.1.1.1,8.8.8.8:53,google.com" --interval 0.5
```
Формат узла: `хост` или `хост:порт` (`[::1]:8080` — для IPv6 со скобками); порт — это TCP-порт проверки, по умолчанию 443.

## ⌨ Горячие клавиши в терминале

| Клавиша | Действие |
|:-------:|:---------|
| `S` | Запустить тест скорости скачивания и отдачи (**Speedtest**) |
| `T` | Запустить трассировку маршрута (**Traceroute / MTR**) |
| `E` | Экспортировать отчет текущей сессии в файлы `.json` и `.csv` |
| `W` | Открыть Web-дашборд в браузере (если запущен с `--web`) |
| `Q` | Завершить работу приложения с авто-сохранением сессии (то же — `Ctrl+C`) |

## 🛠 Параметры командной строки (CLI)

```
usage: main.py [-h] [-H HOSTS] [-i INTERVAL] [-t TIMEOUT] [-m {auto,tcp,icmp,subprocess}] [-w] [-p PORT] [-s]

Параметры:
  -h, --help            Показать справку по аргументам
  -H, --hosts HOSTS     Список хостов через запятую: host или host:port (например: '1.1.1.1,8.8.8.8:53,google.com')
  -i, --interval N      Интервал проверки в секундах, > 0 (по умолчанию 1.0)
  -t, --timeout N       Таймаут одного пинга в секундах, > 0 (по умолчанию 2.0)
  -m, --mode MODE       Режим пинга: auto, tcp, icmp, subprocess (по умолчанию auto)
  -w, --web             Включить встроенный Web Dashboard
  -p, --port PORT       Порт Web Dashboard, 1–65535 (по умолчанию 8080)
  -s, --sound           Включить звуковые оповещения при сбоях
```

Код выхода: `0` — штатное завершение, `2` — ошибка аргументов или занятый порт веб-интерфейса.
